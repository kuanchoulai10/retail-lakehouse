# Pytest e2e without a query engine (KCL-102) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `platform/25-lakehouse-control-plane/e2e.sh` with a pytest e2e that writes and reads Iceberg tables through PyIceberg (no Trino), runs in the cluster as a pod built from the production backend image, cleans up after itself, and splits its scenarios into `critical` and `full`.

**Architecture:** The e2e is a black-box package `e2e/` beside `tests/` in the backend directory. It talks to the platform only over the network: the table maintenance API, Polaris (catalog and management APIs) with its own principal, RustFS and Temporal. An image `table-maintenance-e2e` is built `FROM` the production backend image with the `e2e` dependency group and the `e2e/` package added; the production image is unchanged. A runner script starts one pod per run; an init container (holding the platform's Polaris credential) ensures the e2e principal and hands its fresh credentials to the test container through an `emptyDir`, so the tests never hold the platform credential.

**Tech Stack:** pytest, PyIceberg with `pyiceberg-core`, pyarrow (S3 listing), httpx, temporalio client, bash runner, kubectl.

**Spec:** Linear KCL-102 (description and its completion conditions), read 2026-11-24.

## Global Constraints

- e2e must run with Trino stopped; nothing in `e2e/` talks to a query engine.
- The production image's content does not change: no `e2e/`, no pytest, no `pyiceberg-core`.
- Each scenario uses names unique to the run and cleans up whether it passes or fails; two runs in a row pass.
- Gate rules from root `CLAUDE.md`: cluster tests in `tasks/gates/<gate>/<gate>.yml`, written with `summary`.
- e2e uses its own Polaris principal (`tm-e2e`), not the platform's credential.
- Delete `e2e.sh` only after every check it makes has a home in the new e2e (or a ruling for why not).
- Never `cd`; `uv run`; `KUBE_CONTEXT=retail-lakehouse`.

## Review Focus

- A scenario that fails half way still removes its tables, namespace, policies, attachments, catalog and S3 prefix, and the pod is deleted.
- The platform's Polaris credential never reaches the test container's environment or the logs.
- A rerun right after a failed run passes (no fixed names, no leftover state that changes the outcome).
- The production backend image is byte-for-byte what the same source builds today (its tag ignores `e2e/`).
- A pod that never starts (image missing, init failure) fails the runner within a bounded time with the reason, instead of hanging.

## Rulings made while planning (the user delegated decisions)

- Ruling: the e2e lives in `src/data-platform/backend/e2e/`, a package beside `tests/` — it reuses the backend's lockfile, linters and build context, and stays black-box by an import-linter contract (no `base`, `bootstrap`, `context`) — cost if wrong: moving one directory.
- Ruling: the e2e image is a separate `e2e.Dockerfile` (`FROM` the production image by build arg) with its own `e2e.Dockerfile.dockerignore`, and the backend `.dockerignore` gains `e2e/` — a stage inside the production Dockerfile could not see `e2e/` without changing what the production image ignores — cost if wrong: folding two files into one.
- Ruling: `BACKEND_TAG` ignores `e2e/`, `e2e.Dockerfile*` and `requirements-e2e.txt`; the e2e image tag covers the whole backend directory — so changing a test does not redeploy the platform — cost if wrong: a redeploy the tag hid.
- Ruling: the e2e principal gets a catalog role on `iceberg` with `CATALOG_MANAGE_CONTENT` for PyIceberg, and the `service_admin` principal role to read back catalogs the round trip creates through the API — Polaris has no narrower grant for a catalog that does not exist yet — cost if wrong: a test principal with admin reach on a dev or staging cluster.
- Ruling: the principal is kept between runs (it is the e2e's identity, like a service account); its credentials are rotated on each run and live only in the pod's `emptyDir` — cost if wrong: one Polaris principal left on the cluster by design.
- Ruling: S3 access uses the RustFS key the platform's `table-maintenance-s3` Secret holds — RustFS has a single account on this platform and Spark uses it too — cost if wrong: an e2e that reads storage with the platform's key.
- Ruling: table records, run records and reconciliation records the platform keeps about the e2e's dropped tables stay; "nothing left" means no catalog objects, policies, attachments, S3 prefixes, pods or running workflows — the platform has no API to delete history and it is the platform's data, not the e2e's — cost if wrong: rows in the backend database per run.
- Ruling: `gates:pre-merge:e2e-critical-test` runs the `critical` scenarios when `KUBE_CONTEXT` is given and otherwise keeps its `TODO://` line for the ephemeral platform — the issue leaves the ephemeral platform out of scope — cost if wrong: none.
- Ruling: the delete-file compaction case leaves the e2e (PyIceberg deletes rewrite files); it moves to the Trino compatibility issue, as KCL-102 says.

### Task 1: The e2e package and its support code

**Files:**
- Create: `src/data-platform/backend/e2e/__init__.py`, `e2e/support/{__init__,wait_until,cleanup_stack,unique_suffix,e2e_settings}.py`, `e2e/conftest.py`
- Create: `src/data-platform/backend/tests/e2e_support/test_wait_until.py`, `test_cleanup_stack.py`, `test_unique_suffix.py`, `test_e2e_settings.py`
- Modify: `.importlinter` (root package `e2e`, contract `e2e-black-box`), `pyproject.toml` (isort first party `e2e`), `.dockerignore` (`e2e/`), `tests/architecture` files that list top-level directories or the contract count, backend `CLAUDE.md` contract count.

**Interfaces (produces):**
- `wait_until(probe: Callable[[], T | None], *, timeout: float, interval: float, what: str, clock=time.monotonic, sleep=time.sleep) -> T` — calls `probe` until it returns something other than `None`; raises `TimeoutError(f"{what} not seen within {timeout:.0f}s; last: {last!r}")` where `last` is the last value or exception text.
- `CleanupStack` — `push(what: str, action: Callable[[], object])`; `run() -> list[str]` runs actions newest first, every one even when one raises, returns `["<what>: <error>", ...]`.
- `unique_suffix(random=secrets.token_hex) -> str` — 8 lowercase hex characters.
- `E2eSettings.from_environment(environ: Mapping[str, str]) -> E2eSettings` — frozen dataclass: `api_url`, `catalog_uri`, `management_uri`, `scope`, `catalog`, `polaris_credential` (read from the file named by `E2E_POLARIS_CREDENTIAL_FILE`), `s3_endpoint`, `s3_region`, `s3_access_key_id`, `s3_secret_access_key`, `temporal_address`, `temporal_namespace`; a missing variable raises `KeyError` naming it; `repr` hides the three secrets.
- `conftest.py` fixtures (session unless noted): `settings`, `suffix`, `api` (`httpx.Client`), `polaris_token`, `polaris` (helper with `catalog(method, path, json=None)` / `management(...)` returning `httpx.Response`), `iceberg` (PyIceberg `RestCatalog` for `settings.catalog`), `s3` (`pyarrow.fs.S3FileSystem`), `temporal` (connected `temporalio.client.Client`), function-scoped `cleanup` (a `CleanupStack` run at teardown; a non-empty error list fails the test with every line). Markers `critical` and `full` are registered and `--strict-markers` is on.

- [ ] Step 1: write the unit tests: `wait_until` returns the first non-None value; raises `TimeoutError` naming `what` and the last value after the fake clock passes `timeout`; an exception from `probe` counts as "not yet" and its text is the `last`. `CleanupStack.run` order is newest first, a raising action does not stop the rest, errors read `"<what>: <error>"`. `unique_suffix` is 8 lowercase hex. `E2eSettings` reads every variable, reads the credential file, raises `KeyError` naming a missing one, and its `repr` holds none of the secret values.
- [ ] Step 2: run them, watch them fail (import errors).
- [ ] Step 3: implement; add the import-linter contract and the first-party entry; fix the architecture tests the new top-level package trips.

**Interfaces:** `ensure_principal(client: httpx.Client, *, catalog: str, principal: str = "tm-e2e") -> str` returns `"<client_id>:<client_secret>"`. It creates (or keeps) principal `tm-e2e`, principal role `tm_e2e`, catalog role `tm_e2e` on `catalog` with grant `CATALOG_MANAGE_CONTENT`, assigns the catalog role to the principal role, the principal roles `tm_e2e` and `service_admin` to the principal, then rotates the credentials (`POST /principals/tm-e2e/rotate`).
