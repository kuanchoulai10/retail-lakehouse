# Identity (Keycloak)

Deploys Keycloak 26.8.2 and its PostgreSQL 17.11 database into the `identity` namespace (ambient mesh, gateway routes allowed), and serves Keycloak under `/keycloak` on `platform-gateway`. The realm `retail-lakehouse` is imported at the first start from `keycloak-realm-configmap.yaml`. Single sign-on for the platform UIs is built on it.

## Deployed Resources

```
Namespace: identity
├── keycloak-db           (Deployment, strategy Recreate, postgres:17.11-alpine)
├── keycloak-db           (Service, port 5432)
├── keycloak-db           (PersistentVolumeClaim, 2Gi)
├── keycloak              (Deployment, quay.io/keycloak/keycloak:26.8.2)
├── keycloak              (Service, http 8080, management 9000)
├── keycloak              (HTTPRoute on platform-gateway, PathPrefix /keycloak, no rewrite)
├── keycloak-realm        (ConfigMap, realm JSON with ${…} placeholders)
├── public-origin         (ConfigMap, key origin, rewritten on every bootstrap)
├── keycloak-db           (Secret: username, password, database)
├── keycloak-admin        (Secret: username, password, Keycloak bootstrap admin of the master realm)
├── keycloak-clients      (Secret: oauth2-proxy-client-secret, trino-client-secret,
│                          platform-validate-client-secret, platform-admin-password)
└── oauth2-proxy-cookie   (Secret: cookie-secret, 32 random bytes, URL-safe base64)
```

The four Secrets are generated by `bootstrap.sh` the first time (NotFound check plus `kubectl create`) and never rewritten: rerunning the bootstrap keeps every value. They are not in the repository and disappear with `task offboard`.

## Services

| Service | Port | Purpose |
|---------|------|---------|
| `keycloak.identity.svc.cluster.local` | 8080 | Keycloak HTTP, relative path `/keycloak` |
| `keycloak.identity.svc.cluster.local` | 9000 | Management: `/keycloak/health/{started,ready,live}`, `/keycloak/metrics` |
| `keycloak-db.identity.svc.cluster.local` | 5432 | PostgreSQL, database and user `keycloak` |

## Public origin and issuer

`bootstrap.sh` takes the public origin from `origin::public` (`scripts/utils/origin.sh`: `PUBLIC_ORIGIN` if set, otherwise `https://<tailscale DNS name>:8591`) and writes it to the ConfigMap `public-origin`. Keycloak runs with `KC_HOSTNAME=<origin>/keycloak` and `KC_HOSTNAME_BACKCHANNEL_DYNAMIC=true`:

- Tokens and the discovery `issuer` are always `<origin>/keycloak/realms/retail-lakehouse`, whichever URL the request came in on.
- Backchannel endpoints (token, JWKS, userinfo) in the discovery document follow the request, so a pod that asks `http://keycloak.identity.svc.cluster.local:8080/keycloak/realms/retail-lakehouse/.well-known/openid-configuration` gets in-cluster token and JWKS URLs.

Other settings: `KC_HTTP_ENABLED=true` (TLS ends at `tailscale serve`), `KC_PROXY_HEADERS=xforwarded`, health and metrics on, `KC_CACHE=local` (one replica), heap `-Xms256m -Xmx512m`.

## Realm `retail-lakehouse`

| Client | Kind | Redirect URIs | Audience mapper |
|--------|------|---------------|-----------------|
| `oauth2-proxy` | confidential, standard flow | `<origin>/sso/callback` | adds `oauth2-proxy` |
| `trino` | confidential, standard flow | `<origin>/oauth2/callback`, `https://localhost:8443/oauth2/callback` | adds `trino` |
| `platform-validate` | confidential, service account only | none | adds `oauth2-proxy` |

The human user `platform-admin` (email `platform-admin@retail-lakehouse.local`, verified, first and last name set, so no required action at first login) has a permanent password. The service account user of `platform-validate` has a verified email `platform-validate@retail-lakehouse.local`. SSO sessions last 12 hours.

The realm JSON references the origin and every secret through Keycloak import placeholders (`${PUBLIC_ORIGIN}`, `${OAUTH2_PROXY_CLIENT_SECRET}`, `${TRINO_CLIENT_SECRET}`, `${PLATFORM_VALIDATE_CLIENT_SECRET}`, `${PLATFORM_ADMIN_PASSWORD}`), filled from the pod environment, so no manifest holds the origin or a secret.

### Realm edits on a running cluster are manual

Keycloak starts with `--import-realm`, which only creates a missing realm (`Realm 'retail-lakehouse' already exists. Import skipped`). Editing `keycloak-realm-configmap.yaml` and rerunning the bootstrap changes nothing in a realm that already exists, and neither does a changed public origin (the bootstrap restarts Keycloak so its hostname follows, but the redirect URIs stay). Apply such changes by hand in the admin console or with `kcadm.sh`, or re-onboard.

## Reading the passwords

The `platform-admin` password (the user that logs in to the platform UIs):

```bash
kubectl get secret keycloak-clients \
  -o jsonpath='{.data.platform-admin-password}' \
  --namespace identity \
  --context retail-lakehouse | base64 -d; echo
```

The Keycloak admin of the master realm (`/keycloak/admin/`): Secret `keycloak-admin`, keys `username` and `password`, read the same way.

## Validation token

`gateway::token` (`scripts/utils/gateway.sh`) prints a `platform-validate` access token. It reads the client secret from `identity/keycloak-clients` and posts a client credentials grant to `/keycloak/realms/retail-lakehouse/protocol/openid-connect/token` through the gateway (the same port-forward as `gateway::curl`, since the host cannot resolve cluster DNS). It returns 1 when the Secret does not exist.

## Break-glass

Once the login gate is on the gateway, it fails closed: with Keycloak down no UI opens through the gateway. Skip the gateway and port-forward straight to the UI's Service, for example:

```bash
kubectl port-forward service/temporal-web 8080:8080 --namespace temporal --context retail-lakehouse
```

## Sync Wave

Wave 13, after `12-platform-gateway` and before every wave that validates through the gateway.

## Installation

```bash
KUBE_CONTEXT=retail-lakehouse bash platform/13-identity/bootstrap.sh
```

## Validation

```bash
KUBE_CONTEXT=retail-lakehouse bash platform/13-identity/validate.sh
```

Checks the ambient and gateway labels, the key names of the four Secrets, both rollouts, HBONE for every pod, the HTTPRoute, the discovery `issuer` through the gateway, and that `gateway::token` returns a token whose `iss` is the public issuer and whose `aud` contains `oauth2-proxy`.
